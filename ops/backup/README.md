# Резервное копирование Fizira

`create-backup.sh` создаёт согласованный контрольный снимок текущего российского
Supabase:

- PostgreSQL custom dump со схемами Auth и данными приложения;
- физические объекты Storage;
- исходники Edge Functions;
- конфигурацию self-hosted Supabase, включая `.env` и другие секреты,
  необходимые для восстановления после полной потери сервера;
- контрольные суммы SHA-256 и метаданные.

По умолчанию результат создаётся в `/root/fizira-backups/<UTC timestamp>` с
правами только для root. Частичный снимок удаляется при ошибке, а успешным
считается только архив, который прошёл проверку `pg_restore`, `tar` и SHA-256.
Незашифрованный снимок содержит персональные данные и серверные секреты, поэтому
его нельзя переносить за пределы сервера или оставлять доступным другим
пользователям.

## Запуск

```bash
sudo bash create-backup.sh
```

Можно переопределить пути переменными `FIZIRA_PROJECT_ROOT`,
`FIZIRA_BACKUP_ROOT` и имя контейнера через `FIZIRA_DB_CONTAINER`.

## Проверка восстановления

`restore-test.sh` восстанавливает PostgreSQL в изолированную временную базу,
проверяет чтение критических таблиц и удаляет временную базу. Рабочая база при
этом не изменяется. Проверка Storage и Functions подтверждает целостность
архивов, но не разворачивает отдельный чистый экземпляр Supabase.

```bash
sudo bash restore-test.sh /root/fizira-backups/<UTC timestamp>
```

## Автоматический зашифрованный backup

`automated-backup.sh` выполняет полный безопасный цикл:

1. создаёт локальный снимок;
2. восстанавливает PostgreSQL во временную базу;
3. шифрует снимок AES-256-CBC с PBKDF2;
4. проверяет расшифровку;
5. загружает архив через `rclone` в отдельное объектное хранилище;
6. повторно читает загруженный объект и сверяет SHA-256;
7. удаляет незашифрованный снимок только после успешной внешней проверки.

Пароль хранится только в `/etc/fizira/backup-passphrase` с владельцем `root` и
правами `600`. S3-ключи хранятся в root-конфигурации `rclone`. Эти секреты
нельзя сохранять в Git или вписывать в командную строку.

Установка файлов и systemd-таймера:

```bash
sudo bash install.sh
```

Установщик намеренно не включает таймер. До включения необходимо:

- настроить отдельный российский S3-compatible bucket как rclone remote
  `fizira-offsite`;
- заполнить `/etc/fizira/backup.env`;
- записать пароль в `/etc/fizira/backup-passphrase` и установить права `600`;
- запустить `sudo systemctl start fizira-backup.service` и получить
  `AUTOMATED_BACKUP_OK`;
- только затем выполнить
  `sudo systemctl enable --now fizira-backup.timer`.

Таймер запускается ежедневно около 03:30 по московскому времени, хранит семь
последних дней зашифрованных локальных копий и не удаляет удалённые объекты.
Удалённую ротацию следует задавать lifecycle-правилом самого bucket, чтобы
ошибка в серверном скрипте не могла массово удалить резервные копии.

## Ограничения

Локальная незашифрованная копия на том же сервере защищает только от части
ошибок. Она не защищает от потери сервера или доступа root. Полноценной копия
становится только после шифрования, выгрузки в отдельное российское объектное
хранилище и успешной проверки загруженного объекта.

Поскольку автоматический архив включает `.env`, JWT и другие серверные секреты,
утрата пароля шифрования делает полное восстановление невозможным. Пароль нужно
хранить в менеджере паролей отдельно от сервера и S3-аккаунта.
