## 2. Причины проблем

- Редактор, ручное сохранение и экспорт имели отдельные обработчики и промежуточные состояния. Сохранение перечитывало данные карточки и перестраивало форму.
- Перед экспортом было лишнее подтверждение; сформированный File не сопровождался полноценным экраном готового отчёта.
- Текущий серверный PDF использовал простой текстовый шаблон без логотипа, визуальной иерархии и колонтитулов.
- Нативный iframe не гарантирует видимый PDF: в используемом Chromium просмотрщик отсутствует. Простая проверка `blob:` URL этого не обнаруживала.

## 8. Autosave

Задержка 650 мс после ввода; записи сериализованы. Новый черновик вставляется один раз. Если текст изменился во время записи, цикл сохраняет следующую актуальную версию. Обновление ограничено `id`, `patient_id`, `therapist_id`, editable publication status и сохранённым `updated_at` (CAS).

Генерация PDF, закрытие и обычная навигация внутри текущего аккаунта ждут последнего сохранения. При ошибке переход не заменяет редактор. Повторное открытие истории берёт свежую запись после сохранения, включая новый `updated_at`. Очистка всех разделов существующего черновика сохраняется; пустой текст отдельно блокирует генерацию PDF.

Поздние AI/save/PDF ответы проверяют аккаунт, пациента, подключённый DOM и поколение редактора. После удаления представления таймеры и preview освобождаются. При смене аккаунта старый UI немедленно удаляется существующим Auth flow; сохранение под новым аккаунтом не запускается. Завершение вкладки/браузера не имеет гарантированного сетевого flush.

Autosave применяется к первичному отчёту. Существующая запись отчёта о занятии с фотографиями сохраняет свой процесс ручного сохранения: это несколько связанных таблиц и Storage операций. Общий готовый PDF/preview/share доступен и в этом редакторе.

## 9. PDF и предпросмотр

Сохранён существующий `pdf-lib` renderer и контракт snapshot. A4, встроенный Noto Sans для кириллицы, утверждённый логотип, дата/ребёнок, различимые разделы, переносы по ширине и обработка длинных слов, продолжения страниц, контакты специалиста, подпись Fizira и номер `N / total`. Пустые разделы пропускаются. Сохранены пределы размера snapshot, времени, страниц и PDF; font subsetting остаётся отключённым из-за известной проблемы self-hosted Edge Runtime.

Внутри приложения локальный PDF.js 5.6.205 рисует первую страницу **того же PDF**, который скачивается и передаётся; показано общее число страниц. Для полного документа есть вторичная ссылка, не заменяющая экран приложения. Модули загружаются после генерации с Fizira; внешние сервисы/шрифты и eval/Wasm не используются. При ошибке предпросмотра сохраняется готовый файл и отображается понятный fallback. Лицензия и контрольные суммы: [pdf-preview-dependency.md](pdf-preview-dependency.md).

Опубликованные/архивные отчёты открываются только для чтения из `published_snapshot`. Серверная логика возврата исходных неизменяемых PDF и проверки их хеша не изменена; отсутствующий legacy текст не подменяется текущими клиническими полями.

## 10. Share и независимость от Parent Cabinet

`navigator.share({files:[file]})` вызывается непосредственно при нажатии, до первого await, сохраняя user activation. Перед этим File уже готов. Передача не создаёт приглашение, аккаунт родителя, доступ к карточке или публикацию. Используется существующий owner-only endpoint с `mode: 'export'`.

Отмена Share Sheet сохраняет File и все действия. При отсутствии file sharing или ошибке файл передаётся браузеру для скачивания, а UI объясняет ручную отправку из файлов/загрузок. Страница остаётся на текущем отчёте. Blob URLs и preview задачи освобождаются при редактировании/смене представления.
